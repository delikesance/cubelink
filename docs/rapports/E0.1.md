# E0.1 : faux serveurs d'authentification

- Créés : `tests-fixtures/auth/{server.mjs,server.test.mjs,README.md}`. Un seul processus Node (http natif, ESM, 127.0.0.1), ligne `ready` JSON sur stdout.
- Formats calqués sur les clients Rust (device.rs, xbox.rs, minecraft.rs) : `/devicecode`, `/token` (device_code + refresh_token), `/user/authenticate`, `/xsts/authorize`, `/authentication/login_with_xbox`, `/entitlements/mcstore`, `/minecraft/profile`.
- Scénarios via `POST /__control`, état via `GET /__state` (requêtes reçues). Profil fixe TestPlayer, jetons `fake-*`, domaines `.invalid`.
- Intervalle device code = 1 s (le client Rust dort `interval` secondes avant chaque poll ; `authorization_pending_then_ok` coûte donc ~3 s).
- MANQUE POUR LE TEAM LEAD : l'app n'a AUCUN moyen de surcharger les URLs. `commands_auth.rs` appelle `DeviceCodeClient::new`, `XboxClient::new()`, `MinecraftClient::new()` (URLs par défaut codées en dur) ; seul `CUBELINK_MS_CLIENT_ID` est lu. Il faut ajouter dans src-tauri (ex. sous `CUBELINK_TEST_MODE`) des variables du type `CUBELINK_AUTH_MS_URL` (-> `with_base_url`, doit inclure `/consumers/oauth2/v2.0` ou non : le fake accepte les deux), `CUBELINK_AUTH_XBOX_URL` et `CUBELINK_AUTH_XSTS_URL` (-> `with_base_urls`), `CUBELINK_AUTH_MC_URL` (-> `with_base_url`), toutes = `base` du fake. Aussi : pas de refresh du jeton Microsoft dans l'app (U13), donc `token_expired_then_refresh` n'est exerçable que contre le serveur lui-même tant que le refresh n'existe pas.
