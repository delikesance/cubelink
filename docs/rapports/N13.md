# N13 : reprise après coupure (p2p/src/transfer/resume.rs)

- `ResumableReceive::{start, recover}(id, plan, peer, Arc<transport>, store_root, Arc<StoreIndex>, ResumeConfig)` puis `run(&progress)`, `pause()`, `resume()`, `cancel()`, `state()` ; `recover` (et non `resume`, déjà pris par la méthode) relit le journal.
- Journal `<store_root>/.transfers/<id>.json` (atomique : tmp + sync + rename) : version, fichiers terminés (sha256, taille), partiels (offset + sha256 du préfixe). Partiels : `.tmp/<sha>.resume.part`. Journal corrompu / autre version / autre id : ignoré, on repart du cache ; partiel sans entrée vérifiable : supprimé.
- Jamais de confiance au journal : à chaque tentative le préfixe est re-haché (`verify_and_truncate`), puis sha256 + taille finaux ; reste = plan - cache (index + fichier présent) - `skip_sha256`.
- Retry : `RetryPolicy` (base x 2^n, plafond, gigue), uniquement `Error::Network` ; Integrity/Auth/NotFound/Invalid immédiats, Cancelled jamais retenté ; compteur remis à 0 si progrès. Sommeil injectable (`SleepFn`, temps simulé en test). Pause = pas une erreur réseau. Annulation : partiels + journal supprimés. `purge_orphans(store_root, age)` (7 j par défaut, appelé à l'ouverture). Un seul transfert actif par journal (registre statique).
- Tests (10 verts, clippy -D warnings OK) : coupure puis reprise auto (octets exacts), redémarrage via journal, journal corrompu/autre version, partiel altéré, backoff + épuisement + gigue, pause/reprise, annulation, Integrity non retentée, unicité, purge.
- Couche autonome : `receive_plan` n'est pas utilisé (il ignore `resume_from` et crée un .part aléatoire) ; resume.rs appelle `transport.fetch` directement. Les tests utilisent un transport `Flaky` local (MemTransport ne sait ni couper ni reprendre).
- Changements minimes à faire ailleurs : (1) `MemTransport::fetch` et `IrohTransport::fetch` doivent honorer `resume_from` (ouvrir `dest` en append, lire la source depuis cet offset ; iroh-blobs : requête de ranges BLAKE3), sinon ils retransfèrent tout (correct mais sans gain) ; (2) option : `MemTransport` avec « couper après N octets » ; (3) recv.rs pourrait déléguer à resume.rs.
- Limite : sur crash dur (sans erreur), le dernier checkpoint est celui de la dernière interruption ; un partiel sans entrée de journal est rejeté (prudence). Un checkpoint périodique demanderait un hash incrémental côté transport.
