# A4 : stockage chiffré des jetons (`core/src/auth/tokens.rs`)

- `StoredTokens` (refresh Microsoft, jeton Minecraft, deux expirations en secondes Unix, `Profile`) ; `Debug` masque les jetons.
- `TokenStore::new(path, key_provider)` : `save`, `load -> Result<Option<_>>`, `clear`, `needs_refresh(now, margin)` (vrai si rien de stocké ou jeton expirant dans la marge).
- Format : `CLT1 || nonce 12 o aléatoire par écriture || AES-256-GCM` (magic en AAD) ; écriture atomique `.tmp` + rename, 0600 sous Unix.
- Fichier altéré, tronqué ou mauvaise clé : `Error::Auth` explicite, sans contenu clair ; aucun panic, aucun appel réseau.
- `KeyProvider` (32 octets), `FileKeyProvider` (clé générée au premier usage, `create_new`), `StaticKeyProvider` (tests).
- Limite honnête : le fichier-clé à côté des données ne protège pas contre un autre processus de l'utilisateur ; sous Windows aucune ACL n'est posée. Le branchement sur Credential Manager est hors périmètre.
- Le rafraîchissement réel se branchera sur `auth::device` ; ici seule la logique d'expiration existe.
- Tests : 10 verts (aller-retour, nonce, altéré, mauvaise clé, tronqué, absent, clear, needs_refresh, Debug, fichier-clé). Clippy `-D warnings` OK.
