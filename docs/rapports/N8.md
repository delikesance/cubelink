# N8 : présence (p2p/src/presence.rs)

- ALPN `cubelink/presence/1` : ping `PING` (4 octets), réponse `PONG\x01` (5 octets), aucune donnée personnelle ; lectures bornées et délais côté serveur.
- Serveur : `PresenceService::handler()` (`ProtocolHandler`) à enregistrer dans le `Router` de l'application (un seul routeur par endpoint). Non-ami : `conn.close` immédiat, aucun octet renvoyé. Limite iroh : la poignée de main QUIC précède notre code (l'inconnu voit la connexion s'établir, rien de plus).
- Client : `PresenceService::start(endpoint, Arc<dyn FriendLookup>, EventSink)` ; `PresenceConfig` (30 s +/- 20 % de gigue, délai 5 s, 2 échecs avant hors ligne, 8 sondes max via `Semaphore` + `buffer_unordered`).
- `FriendLookup` (`friend_keys`, `is_friend`) implémenté directement pour `FriendsDb`. `PeerAuthorizer` (N11) travaille sur des clés texte : non réutilisé tel quel.
- Événements `PresenceEvent{public_key, presence}` uniquement aux changements ; état initial implicite = hors ligne ; `snapshot()`, `probe_now(key)`, `probe_all()`, `add_addr(EndpointAddr)` (adresse directe sans découverte), `stop()` (attend la tâche ; `Drop` l'abandonne sinon).
- Tests (7 verts) : machine d'états et événements, timeout, concurrence <= 8 sur 40 amis, tours périodiques + arrêt propre (plus d'appels, état libéré), deux endpoints iroh sans relais (en ligne, arrêt -> hors ligne après 2 échecs, non-ami sans aucun octet), adaptateur `FriendsDb`.
- Écart : `tokio::time::pause` indisponible (feature `test-util` absente de `tokio` full, Cargo.toml interdit) : tests en temps réel avec durées courtes (~2 s au total).
