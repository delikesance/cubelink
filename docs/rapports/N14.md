# N14 - Tunnel de jeu P2P (p2p/src/tunnel.rs)

- API : `HostTunnel::start(endpoint, world_port, Arc<dyn TunnelAuthorizer>)`, `GuestTunnel::connect(endpoint, impl Into<EndpointAddr>)` (`local_port`, `path_kind()`, `stats()`, `closed()`, `stop()`), ALPN `cubelink/tunnel/1`, `TunnelConfig` (8 connexions, connexion 10 s, inactivité 120 s).
- `PeerAuthorizer` (N11) prend `&str` : trait local `TunnelAuthorizer { is_allowed(&[u8;32]) }` + `AllowKeys`. Un adaptateur FriendsDb est à brancher à l'intégration.
- Sécurité : pair refusé = `conn.close` avant tout accept_bi ; l'hôte ne se connecte qu'à 127.0.0.1:world_port ; invité n'écoute que sur 127.0.0.1 ; limite appliquée des deux côtés (excédent fermé/reset).
- Arrêt : JoinSet + `ConnGuard` (fermeture QUIC au drop) ; `stop()`/`Drop` abandonnent tout. Half-close propagé (finish/shutdown), erreurs => reset des flux.
- `path_kind()` (Direct/Relay/Unknown) via `conn.paths()` côté invité ; stats : actives, totales, rejetées, octets.
- Contraintes : l'endpoint hôte doit inclure l'ALPN et être dédié au tunnel (accept direct, pas de Router) ; le client TCP doit parler le premier (OK pour Minecraft) car le flux QUIC n'est visible de l'hôte qu'à la 1re écriture.
- Tests (6, tous OK, ~2,5 s) : écho+handshake, 5 sessions simultanées, pair refusé, arrêt hôte, limite, 10 Mo intègres. Clippy `-D warnings` propre.
