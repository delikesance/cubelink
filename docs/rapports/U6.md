# U6 : écran Paramètres

- Fichiers : `src/screens/Settings/{index.tsx,settings.css,index.test.tsx}`. lint, test:front (5 tests Settings), build OK.
- Fidèle au design : 4 sections (Réseau P2P, Codes, Cache et partage, Crédits et licences), onglets verticaux avec flèches/Home/End, lien `#/legal`, fermeture `#/main`.
- Enregistrement à la modification via `settingsSet`, « Enregistré » en `role=status` aria-live, erreur en `role=alert`. Test de persistance (démontage/remontage avec le même faux service).
- Le design n'a ni mémoire, ni chemin Java, ni déconnexion : `validateRam` (512–65536) et `validateJavaPath` sont exportés et testés mais sans champ affiché.
- Écarts de type `Settings` (à étendre par le team lead) : « Passer toujours par le relais » (`relay_only`, distinct de `allow_relay`) et « Envoyer des mods à mes amis » (`share_mods`) sont envoyés comme champs additionnels ; `language`, `default_ram_mb`, `java_path`, `trust_default`, `close_on_launch` n'ont pas de réglage dans le design.
- Services manquants : test de connexion, taille/vidage du cache, code de vérification (affichés « Indisponible » ou « pas encore disponible » ; props `testConnection`/`clearCache` prévues pour le branchement).
- Le design affichait des données factices (14 h 03, 12,4 Go, clé 3f9a…5e14) : non reprises.
