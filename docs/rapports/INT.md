# INT : IrohBackend (src-tauri)
Fichiers : `iroh_backend.rs` (backend, `start_app`, handlers), `authz.rs` (FriendsDb -> PeerAuthorizer/TunnelAuthorizer/FriendLookup, `share_mods` ne gate que fichiers/manifeste), `p2p_backend.rs` (trait étendu : `accept_request/refuse_request`, `fetch_manifest -> HostManifest`, `receive_files(id, Plan, ..) -> Result<_, Error>`, `host_start_sharing/stop`, `code_hints`, `TransferControl` avec crochet), `commands_{friends,join}.rs`, `state.rs` (identity Arc, settings Arc, backend RwLock, `skip_game_install` de test), `lib.rs`, `tests/p2p_integration.rs`. `UnavailableBackend` conservé (20 tests unitaires).
Choix : 1 Endpoint (`relay::build_endpoint`, clé `secret_bytes`, allow_relay/relay_only lus au démarrage), 1 Router (friend, presence, xfer, blobs, manifeste, tunnel). Événements : `friend://request`, `friend://presence`, `transfer://progress` (via_relay par `PathObserver` sur une connexion gardée ; messages « disque plein / fichier corrompu / l'ami s'est déconnecté / Java introuvable »). join_start : reçoit (ResumableReceive, id stable, reprise automatique) -> `create_guest_instance` + `install_manifest_files` (rollback) -> `ensure_game`.
Hôte : `IrohBackend::host_start_sharing(instance_id, world_port)` (aussi dans le trait) ; MANQUE signalé : le front n'a aucune commande pour ça (à ajouter au contrat).
Réimplémenté dans src-tauri faute de Router partageable : (1) `XferControl` et `GatedBlobs` = copies de `Control`/`GatedBlobs` privés de send.rs (+ FsStore hôte `p2p/host-blobs`), car `IrohTransport::serve` crée son propre Router ; l'invité utilise `IrohTransport::new` + `fetch` seulement ; (2) `ManifestHandler` (ALPN `cubelink/manifest/1`) : N11 n'a AUCUN canal de manifeste ; (3) `TunnelBridge` (ProtocolHandler) car `HostTunnel::start` consomme `endpoint.accept()` ; l'invité utilise `GuestTunnel`. Refactor p2p proposé : `IrohTransport::handlers(host) -> (Control, Blobs)`, `HostTunnel::handler()`, canal manifeste dans send.rs.
Écarts/bogues p2p : (a) rustc : `ResumableReceive::run` n'est pas prouvé `Send` (RPITIT de `BlobTransport`, resume.rs:609 `checkpoint`) -> j'exécute via `block_in_place` + `block_on` (runtime multi-thread requis) ; correctif : futurs `+ Send` explicites ou boxés. (b) `relay::build_endpoint` utilise `presets::Minimal` : aucune découverte d'adresses ; sans relais ni adresses dans le code ami, un pair n'est pas joignable (code ami = relais + adresses ; `advertise_addrs` auto si relais coupé). Proposition : preset N0/address lookup. (c) IrohTransport garde chaque blob dans son FsStore (double espace disque côté hôte `ImportMode::Copy` et invité) : prévoir GC/suppression des tags. (d) `Manifest` sans sha1 : mods inconnus impossibles à calculer avant réception ; `unknown_mods` = déclaration de l'hôte (non fiable, filtrée sur les chemins du manifeste), `find_unknown` tourne côté hôte (injectable). (e) `refuse_all` ne notifie pas les demandeurs ; `friend_accept` échoue si le demandeur est parti.
Tests : 20 unitaires + `p2p_integration` (A/B loopback, relais désactivé, 3 runs stables) : demande par code, codes identiques, accept, présence online + événement, manifeste 2 mods + inconnu, plan, join avec coupure au 2e fichier puis reprise, hashes, instance invitée, hôte intact, cache, tunnel vers faux monde, non-ami refusé, `share_mods=false` refusé. Clippy `-D warnings` propre. Non testé : installation réelle loader/Java (sautée), pause/resume en test, chemin relais.
Dépendances : iroh, iroh-blobs, hex, anyhow (déjà ajoutées par le team lead).
