# I3 : lancement et suivi du processus Java (core/src/launch_run.rs)
- `spawn(cmd, log_dir)` / `spawn_with(.., RunOptions)` : tokio::process sans shell, cwd = cmd.cwd, stdout+stderr fusionnés.
- Journal `<log_dir>/latest.log` borné (2 Mio par défaut), rotation vers `latest.log.old` (aussi au lancement).
- Secrets = arguments masqués par `redacted_args()` ; remplacés par `***` dans journal et événements (valeurs < 4 car. ignorées, ex. jeton hors ligne "0").
- `RunningGame{pid, events(), kill(), wait()}` ; `events()` retire le récepteur, le RunningGame doit rester vivant (drop = jeu arrêté, + kill_on_drop).
- Événements `Started/Output/Exited/Failed` ; Output limité en débit (200/s) et jamais bloquant ; code != 0 -> `Failed` en français (rapport `crash-reports` récent, échec au démarrage selon `startup_grace`, dernière ligne).
- `kill()` : terminaison (SIGTERM / taskkill) puis arrêt forcé après `kill_grace` (arbre de processus sous Windows).
- Java/cwd introuvable -> `Error::NotFound` explicite. `launch_state_stream(id, game)` -> `LaunchStateEvent{id,state,message?}` (preparing/running/exited/failed), sans Tauri.
- Tests : 10 (sortie 0 + témoin, sortie 1, crash-report, introuvable, kill, drop, jeton masqué, taille du journal, flux d'états). Clippy -D warnings OK. Aucune fonctionnalité tokio manquante.
