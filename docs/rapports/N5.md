# N5 : base SQLite des amis et demandes (p2p/src/friends_db.rs)

- `FriendsDb::open(path)` / `open_in_memory()` : WAL, `foreign_keys=ON`, `user_version` (SCHEMA_VERSION = 1), migrations incrémentales (`MIGRATIONS`, v0 -> v1 testée).
- Tables `friends` et `requests` (direction `in|out`, index sur `received_at`). rusqlite était déjà dans p2p/Cargo.toml, `mod friends_db` déjà dans lib.rs : rien à ajouter.
- API : add/get/list/remove_friend, set_trust, rename, is_friend, `upsert_request(&FriendRequest, Direction)`, request_count, `list_requests(offset, limit, query)` (tri `received_at` DESC, LIKE échappé avec `ESCAPE '\'`), remove_request, remove_all_requests, `accept_request` (transaction IMMEDIATE, renvoie `Friend` en confiance `Ask`).
- Erreurs : doublon d'ami -> `Invalid("cet ami existe déjà")` ; clé/nom/code invalides -> `Invalid` ; absent -> `NotFound`. Requêtes toutes paramétrées.
- Choix : `list_requests`/`request_count` couvrent les deux directions ; la casse du LIKE n'est insensible qu'en ASCII (limite SQLite).
- Tests : 11 (CRUD, migration, 1000 demandes, tout refuser, accept atomique/rollback, injection, `%`/`_`/`\`, réouverture tempfile, validation) : tous verts.
