# S4 : GC du magasin (core/src/store/gc.rs)
- API : `collect(store_root, &StoreIndex, &GcOptions{dry_run, min_age, remove_orphans}) -> Result<GcReport>`.
- Rapport : `removed` (hashes), `bytes_freed`, `skipped_recent`, `errors`, `orphans`, `removed_orphans`, `removed_dirs`.
- Sécurité : seuls les chemins recalculés par `object_rel_path` sont supprimés, via `safe_join` (refuse `..`, absolu, `\`). Si `rel_path` de l'index diverge, erreur et entrée conservée. Relecture des refs avant suppression.
- Échec disque (dont fichier absent) : erreur dans le rapport, entrée d'index gardée, on continue.
- Orphelins : cherchés dans `xx/yy/` uniquement (hash absent de l'index, ou nom non-hash) ; supprimés si `remove_orphans`, `min_age` respecté (mtime) ; ni liens symboliques ni dossiers.
- Dossiers `yy` puis `xx` vides supprimés (jamais la racine). Rien n'est modifié en `dry_run`.
- Limites : `min_age` se base sur max(created_at, last_used) ; fenêtre de course minime entre relecture et suppression (pas de transaction index+disque). L'API StoreIndex a suffi, mais ne peut pas lister toutes les entrées (orphelins détectés via `contains`).
- Tests : 9 verts (`cargo test -p cubelink-core store::gc`).
