# N11b : reprise honorée dans send.rs

- `MemTransport::fetch` : autorise d'abord (mêmes contrôles qu'à 0, l'offset ne sert jamais à autoriser), puis `resume_from > taille source` ou `> req.size` -> `Error::Invalid`.
- Reprise = `dest` ouvert en append et source lue depuis l'offset, seulement si `dest` fait exactement `resume_from` octets ; sinon repart de 0 (`dest` recréé).
- Tests : `with_cut_after(n)` (une fois) / `with_cut_after_always(n)` (chaque fetch) -> `Error::Network` ; `bytes_transferred()` compte les octets réellement transférés (hors préfixe).
- Tests ajoutés : reprise ne transfère que le reste (100 000 puis 200 000 octets, sha256 final identique), offset incohérent -> 0, hors bornes rejeté, pas de contournement d'autorisation.
- `IrohTransport::fetch` : offset hors bornes rejeté ; pas de plage exposée par l'API utilisée -> iroh-blobs retransfère tout le blob et `export` réécrit `dest` en entier (correct, sans gain réseau) ; `on_bytes` ne signale que `size - resume_from`.
- Intégration : aucun changement requis dans resume.rs/recv.rs (recv.rs passe toujours `resume_from: 0`). Le sha256 final reste vérifié par l'appelant. Le test `Flaky` local de resume.rs pourrait être remplacé par `MemTransport::with_cut_after`.
