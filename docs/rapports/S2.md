# Rapport S2 : index du magasin (core/src/store/index.rs)

- `StoreIndex` : une connexion SQLite (rusqlite) derrière un `Mutex` ; plusieurs instances/connexions possibles sur le même fichier.
- Ouverture : WAL, `synchronous=NORMAL`, `busy_timeout` 30 s ; migrations via `PRAGMA user_version` (v1 table de base, v2 refs/dates), en transaction `IMMEDIATE` (sûr en concurrence, atomique en cas de crash). Schéma plus récent refusé.
- API : `insert` (idempotent, conserve chemin/taille/refs), `get`, `contains`, `add_ref`/`release_ref` (renvoient le nouveau compteur, plancher 0, `NotFound` si absent), `unreferenced`, `remove`, `total_size`, `schema_version`.
- `object_rel_path(sha)` -> `ab/cd/<hash>` ; hash invalide (hors 64 hex minuscules) -> `Error::Invalid` partout.
- Écritures atomiques par instruction ou transaction ; erreurs SQLite mappées sur `Error::Other`.
- Tests (10) : CRUD, idempotence, compteurs, 8 threads x 200 insertions en connexions séparées, instance partagée, réouverture, migration d'un schéma v1, schéma futur, hash invalide. Clippy `-D warnings` OK.
