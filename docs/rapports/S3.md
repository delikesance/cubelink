# S3 - placement hardlink/copie (core/src/store/link.rs)

- API : `link_or_copy(src, dst) -> Result<LinkKind>` (`HardLink | Copy`), `link_into(root, rel_path, src)`, `same_file(a, b)`, `link_or_copy_with` (lien injectable pour les tests).
- Écriture atomique : lien ou copie vers un fichier temporaire voisin, puis `rename` ; le temporaire est supprimé en cas d'échec.
- `dst` existant : si `same_file`, aucune action ; sinon remplacé. Parents créés automatiquement.
- `link_into` rejette (Error::Invalid) `..`, chemins absolus, `\` initial, `:` (lecteur Windows / flux), vide, octet nul ; `/` et `\` acceptés.
- `same_file` : (dev, inode) sous Unix ; sous Windows chemins canoniques, sinon taille + mtime + ctime (limite : une copie préservant tout serait vue comme identique).
- Sémantique : un hardlink partage les données ; modifier l'instance modifie l'objet du cache (traiter en lecture seule ou copier).
- Tests : 5 (hardlink, repli copie, chemins malveillants, idempotence/remplacement, parent créé) ; clippy `-D warnings` propre.
